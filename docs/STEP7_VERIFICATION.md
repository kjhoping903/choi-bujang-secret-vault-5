# 7단계 재확인 계약 점검 — 2026-10-14

## 확인 가능한 계약과 연결 상태

- `docs/DECIDER_REQUEST.md`는 `stepUp: {verified, authAgeSeconds}`를 정의한다.
  이 값만 보고 재인증 확인 요청을 건너뛰지 말라고 명시한다.
- 같은 `subjectId`의 새 로그인이 추가 확인 요청 이후 이루어졌는지 확인하는
  엔진 요청·응답 계약, 확인 API 주소, 재판정 연결 절차는 현재 폴더에서 찾지 못했다.
- 문서가 참조하는 `student-kit/sdp-core/decision-contract.mjs` 원본은 현재 폴더에 없다.
  따라서 운영 엔진에 해당 기능이 없다고 단정하지 않고 계약 준비 여부를 미확인으로 남긴다.
- `src/verify-login.mjs`의 학생 인증 결과는 검증한 사용자 ID이며 재로그인 시각을 반환하지 않는다.
  `api/materials.js`는 로그인·소유자를 검사하지만 `decide`를 호출하지 않는다.
- 판정기의 `stepUp` 가상 입력에 따른 허용은 로컬 계약 연습이다.
  실제 새 로그인 확인, 자료 차단 또는 차단 해제 증거가 아니다.

## 실행한 가상 시험

| 명령 | 결과 |
| --- | --- |
| `npm.cmd run fixture:7` | 정상 사건 allow, 복합 이상 사건 step_up |
| `npm.cmd run decider:test` | 정상·미등록·복합 이상·가상 재확인 4개 통과 |
| `node --test test/decider-input.test.mjs test/decider-step-up.test.mjs` | 10개 통과 |

복합 사건은 judge_fixture 출처, 0~5시, unusual 네트워크,
최근 60초 이내 risk_signal 20회 이상을 함께 검사한다.
실제 위치·접속 이력이나 실측 자료 읽기 횟수로 해석하지 않는다.
기존 기기·경로 규칙과 실제 자료 API는 보존한다.

## 실측 상태

| 항목 | 상태 |
| --- | --- |
| 동일 주체의 새 로그인 시각을 확인하는 운영 계약 | 현재 자료로 미확인 |
| 추가 확인 전 실제 자료 차단 | 미실행 |
| 같은 주체의 새 로그인 후 새 요청 재판정·허용 | 미실행 |
| 실제 엔진·심판 시험 | 미실행 |

운영 계약과 자료 경로의 엔진 연결이 확인된 환경에서만 실측한다.
추가 확인 전 자료가 반환되지 않는지 확인하고, 동일 주체의 새 로그인 시각을
엔진이 검증한 뒤 새 요청을 재판정한다. 판정기 조건뿐 아니라 실제 HTTP 결과를 확인한다.
기록에는 토큰 원문·인증 헤더·개인정보·메모 본문을 넣지 않는다.
기록은 가명 요청 구분, 판정 사유, HTTP 상태와 실행 여부로 제한한다.

현재는 터미널에서 위 가상 시험만 실행하며 화면에서 누를 실측 버튼은 없다.
